Functional Requirement:
-----------------------
- Accept text and an optional expiration time; return a paste ID and short URL.
- Return the paste text, or 404 if it doesn't exist or has expired.
- Open a human friendly page displaying the paste.

Non-Functional Requirement:
---------------------------
- Low latency
- High availability
- Massive scale
- (And so on...)

Assumptions:
-------------
- Write: 1M paste per day = 12 writes / second on average.
- Read: 20M paste views per day = 231 reads / second on average.
- Peak: Assume 10 times the average: roughly 120 writes / second and 2300 reads / second.
- Content Storage: At an average of 10KB per paste, writes add about 10GB / day, or 3.65TB / year before replication, compression, and expiration.
- Read Traffic: 20M x 20KB = 200GB / day of paste content. At the assumed peak, content delivery is rougly 23 MP / second.

API Design:
------------
POST /pastes
GET /pastes/{id}
GET /{id}

DB Schema:
----------
- RDBMS: PostgreSQL or MySQL: {pastes: id, object_key, created_at, expires_at, size_bytes, status}
- Object Storage: AWS S3: key such as pastes/A7kP2mQ9xB; value is the raw text bytes
- Distributed Cache: Redis Cache: key such as pastes/A7kP2mQ9xB; value contains content and expiration metadata
