Functional Requirement:
-----------------------
- Users can create and delete text tweets.
- Tweets may reference to images and videos.
- Users can follow and unfollow other users.
- Users can view home timeline and other user's timeline.
- Timeline ordering is initially reverse chronological.
- Like, replies, search, recommendations, and others. (Let's skip this part as of now)

Non-Functional Requirement:
---------------------------
- Low latency
- High availability
- Massive scale
- (And so on..)

Assumptions:
------------
- 300M active users monthly
-- 100M active users daily
- 50M tweets per day
- 2B home-timeline requests per day
- An average user follows 200 accounts
- A timeline response contains 20 tweets
- Normal peak: 10x than the daily average
- Most traffic consists of reads rather than writes

API Design:
-----------
POST /v1/tweets
DELETE /v1/tweets/{tweetId}
GET /v1/tweets/{tweetId}
GET /v1/users/{userId}/home-timeline?cursor={cursor}&limit=20
PUT /v1/users/{userId}/following/{targetUserId}
DELETE /v1/users/{userId}/following/{targetUserId}
GET /v1/users/{userId}/followers?cursor={cursor}&limit=50
GET /v1/users/{userId}/following?cursor={cursor}&limit=50
POST /v1/media/upload-url

DB Schema:
----------
- User DB: PostgreSQL: {user: user_id, username, display_name, bio, profile_image_key, created_at, status}
- Tweet DB: Cassandra or DynamoDB: {tweet: tweet_id, author_id, text, media_ids, reply_to_tweet_id, created_at, deleted, author_id}
